# Banking OS — output discipline (language rules + final-check)

**Lifted from** the PMM *Banking OS Value Proposition v4.0* (full upstream text: `knowledge/reference/banking-os-v4-UPSTREAM.md`). Apply to every Banking OS deliverable. **The Foil enforces this** (`SHYAMOS_FOIL_L1.md` → output gate).

> **Vocabulary note:** this is v4.0's PMM framing. Where it differs from **your** canon (`banking-os.md` §3 domains, §4 solutions), **your canon's terms win** — adopt the *discipline* (operating-model-primary, sourced proof, no load-bearing directional ranges, Sentinel/Nexus framing), not blindly the wording.

## Language rules
**Always capitalize:** Backbase · Banking OS · AI-native Banking OS · Nexus · Sentinel.

| Don't say | Say instead |
|---|---|
| Chatbot, copilot, virtual assistant | Conversational Banking |
| Agent desktop, portal | Composable Workspace |
| AI governance, guardrails, permissions | Decision Authority (Sentinel) |
| Data layer, Customer 360 | Semantic Layer (Nexus) |
| Platform (meaning the product) | Operating System (Banking OS) |
| Middleware, ESB, API gateway | Connectivity Layer (Grand Central) |
| APA, Agentic Process Automation | Banking operations, Customer Resolution Loops |
| CLO / Coach (standalone) | Relationship Intelligence |

**Never use (retired):** chatbot · APA · Coach-standalone · Northgate · "engagement banking" · "better channels".

## Proof-point discipline
- **Customer proof points** (BMO 81%, Nedbank 70%, First Financial 26%, etc.) — source + attribute to the *specific* customer; never invent. Validate before quoting in a client output.
- **Directional ranges** (10–25%, 20–40%, $150–300M, 3–5×; the 60% whitespace stat) = framing language ONLY, explicitly labelled Backbase-marketing-directional — **never load-bearing in an ROI.** Every quantitative claim anchors to a bank-specific source.

## Final-check rubric (the 13-point gate)
Before any POV / ROI deck / capability assessment / roadmap touching Banking OS positioning ships:
1. Respects the strategic hierarchy (Unified Frontline → Banking OS → Control Plane → outcome)?
2. Operating model is the primary frame (not channels, not apps)?
3. The four operational powers (Understand / Run / Authorize / Optimize) present?
4. The two domains present (your canon's framing)?
5. Workspace stays primary over embedded intelligence ("CSR Workspace with embedded Servicing Agents", not "CSR Agent")?
6. Anchors to Unified Frontline as the category + the operating outcome?
7. Fragmentation framed as the enemy (60% whitespace stat as conversational anchor only, labelled directional, never load-bearing in ROI)?
8. Directional ranges used as framing only; every quantitative claim anchored to a bank-specific source?
9. Sentinel present whenever AI governance is discussed?
10. Nexus described as the operational truth layer (NOT data lake, NOT system of record)?
11. The 3-actor model (Customers + Employees + AI Agents) used when describing the operating model?
12. Customer proof points sourced + attributed + not invented?
13. Language rules respected (no retired terms)?
