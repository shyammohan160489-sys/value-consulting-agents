# Banking OS Alignment Audit — Pipeline Agents (`.claude/agents/*.md`)

**Scope:** 22 agent definitions in `.claude/agents/`. Judged against `knowledge/product/banking-os.md` (control-plane / Nexus+Sentinel / 2-domains→4-solutions / value-leakage-resolution-loop method / three value pools) and `knowledge/design-system/narrative-spine.md` (From→To voice, retired vocabulary).
**Date:** 2026-06-09 · **Auditor:** Banking OS Alignment Checker (read-only).

## Headline finding

The agents are **architecturally one generation behind the canonical product reference.** They are built on an internally-consistent but *superseded* model — the **three-fabric architecture + 13 product lines + lifecycle (Acquire/Activate/Expand/Retain)**, sourced from `knowledge/backbase_platform_lexicon.md`. They do NOT know the banking-os.md model: **Banking OS = control plane**, **Nexus (truth) + Sentinel (governed execution)**, the **2 execution domains → 4 pre-built Solutions** (Digital Banking · Conversational Banking [Assist/Transact/Resolve/Grow] · Relationship Intelligence · Customer Operations / Resolution Loops), **Factory/Missions**, the **three value pools**, and the **value-leakage / customer-resolution-loop assessment method**.

Critically, **only 1 narrative-producing agent (narrative-assembler) gives any product-architecture grounding at all, and it points at the stale lexicon** — and **zero agents instruct the model to read `narrative-spine.md` or `banking-os.md` first.** Every deliverable these agents generate therefore inherits the old story by default.

Note: "Sentinel" appears nowhere in any agent. The agents' "NEXUS" is defined as the evolution of HELIX/Customer Brain (a semantic fabric inside the old 3-fabric model), which is adjacent to but not the same framing as banking-os.md's Nexus-as-control-plane-layer paired with Sentinel.

## Cascade recommendation (highest-leverage single change)

**Add one standard preamble block to every narrative- or deliverable-producing agent** (the 12 flagged HIGH/MED): a mandatory "**Read `knowledge/design-system/narrative-spine.md` and `knowledge/product/banking-os.md` FIRST, and align all output to them**" instruction, plus a short canonical-model crib (Banking OS = control plane; Nexus + Sentinel; 2 domains → 4 Solutions incl. Conversational Banking = Assist/Transact/Resolve/Grow + Resolution Loops; three value pools; value-leakage/resolution-loop method; Factory Missions; "operating models, not channels" / retire "engagement banking" + "digital experience" as lead positioning).

This is the highest-leverage move because the agents are *internally consistent on a stale model* — the problem is not scattered errors but a single missing authority pointer. Today the only product-architecture grounding (narrative-assembler) points at `backbase_platform_lexicon.md`; redirecting that one file plus seeding the preamble fixes the whole cascade in one motion, because every deck/document/assessment inherits its story from these agents. Pair it with a one-line redirect of the two stale source references (`backbase_platform_lexicon.md` → `banking-os.md`) in `narrative-assembler`, `journey-builder`, and `upgrade-analysis`, and the `capability-gap-analyzer` MCP-query fix that removes the literal retired phrase "engagement banking."
